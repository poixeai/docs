## AI 时代的分化效应

AI 正在重塑生产力的格局——但它并非拉平人与人之间的差距，而是放大了它。思维灵活、主动拥抱新工具的人，正借助 AI 实现指数级的成长；而固守旧有认知的人，则在同等时间内越走越远。

普通的 Web 订阅服务虽然便捷，但受限于平台风控，无法满足批量化、程序化的使用需求。API 接口恰恰填补了这一空白——它更适合大规模、稳定的调用场景，但对使用者的技术门槛也更高。

## 适合使用 Poixe 的你

我们建议在具备以下基础认知后，再考虑接入 Poixe：

- **API 计费模式** — 理解 Token 计费与上下文机制，清楚费用是如何产生的
- **RESTful API 调用** — 掌握基本的接口调用方式（HTTP 请求、Headers、Body 结构等）
- **AI 工具配置** — 熟悉你所使用的 AI 应用，例如 Claude Code、Codex，或其他 CLI 客户端工具

如果以上基础尚不具备，建议先完成相应的学习再行接入。

## 关于计费：API 的开销超乎想象

API 调用的费用消耗往往远超预期。以 Claude Code 为例，哪怕你只发出一条 `hi`，系统日志中实际计费的 Token 数量可能高达数万——这是正常现象，不是平台异常，更不是计费错误。

原因在于：每次 API 调用都会携带完整的上下文历史与系统提示词，实际 Token 量远超你看到的那一行文字。平台不会代为设置消费上限，支出完全由你的使用行为决定。

**如果你对账单有疑问，欢迎联系我们——请附上相关日志截图或请求 ID。**

我们的日志系统对每条请求都记录了完整的计费明细，包括处理厂商、Token 分布、实际费用，数据透明可查。在没有任何证据的情况下直接断言"掺水"或"计费有误"，不仅对解决问题毫无帮助，也证明你对 API 计费机制完全陌生。

**谁主张，谁举证——这是基本的沟通常识。**

## 路由与厂商透明度

Poixe 支持自由选择模型厂商。以 `claude-sonnet-4-6` 为例，平台同时接入了多家资源：Anthropic 官方、AWS Bedrock、OpenRouter 等。

| 场景 | 行为 |
|---|---|
| 不指定厂商前缀 | 走 default 路由，系统自动调度 |
| 指定厂商前缀 | 请求由该厂商独立处理，日志中明确标注 |

每条请求的日志页面均会显示实际处理厂商与完整计费信息。如需独立验证，可自行在对应厂商处购买少量 Credits 进行对照测试。

如果你发现某个模型质量存在问题，欢迎带着可复现的测试案例联系我们。

详见：[厂商路由说明](/cn/docs/models-pricing/provider-routing)

## 写给供应商

分布式架构下，渠道数据与上游账单之间存在一定延迟或误差，属于正常的技术现象，无需过度担心。

平台管理 API 提供实时的渠道收益与调用数据（30 秒级缓存）。对于有自动化需求的供应商，接入监控并持续对比是个不错的做法。

如果发现疑似异常，欢迎随时联系团队——带上渠道 ID 和大致时间范围即可，通常很快就能定位。
